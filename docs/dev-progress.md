- 首次全量编译 Claude SDK 需要 `GOGC=15 GOMAXPROCS=1 go build -p 1`，约 8 分钟；之后走缓存。

- `VB_BOT_CONTACT`：运营联系邮箱或网址。导入官方配乐库、音效库时会写进下载请求的 User-Agent（连同 `VB_PUBLIC_URL`），这是 Wikimedia 机器人访问规范的要求；不填可能被拒绝下载（提示「请遵守机器人访问规范」）。导入时对 Wikimedia 每 1.5 秒最多一个请求，遇到 429 按 Retry-After 等待，遇到 403 立即停止。

### 关键约定
- SQLite 开启 WAL + `_txlock=immediate`，连接池 4。事务回调里只能用 `tx`，不要用 `a.DB`。
- API 前缀：用户端 `/api/v1`，管理端 `/api/admin/v1`，开放平台 `/openapi/v1`（API Key 鉴权），实时推送 `/api/v1/events`（SSE，参数 `?access_token=`）。
- 列表接口返回 `{items,total,page,pageSize}`；错误返回 `{error:{code,message,data}}`。
- Go 的 nil 切片会被序列化成 `null`，前端要统一用 `?? []` 兜底。

## 千问语音合成接入（2026-11-02，已完成）

- 适配器：`server/internal/ai/tts/qwen.go`，provider 名 `qwen`（`aliyun` 为别名）。非实时 HTTP：`POST {base}/api/v1/services/audio/tts/SpeechSynthesizer`，默认 base `https://maas.qianwenaiapi.com`（百炼 dashscope.aliyuncs.com 同样适用），返回 URL 后立即下载 wav。（MiniMax 于 2026-11-06 接入；千问声音复刻同日完成，见下文。）
- 模型：qwen-audio-3.1-tts-plus/flash、qwen-audio-3.0-tts-plus/flash、cosyvoice-v3-plus/flash、cosyvoice-v2。**音色与模型一一绑定**，合成时使用音色自己的 `model`，账号上的模型只用于连接测试。
- 内置音色目录：`internal/ai/tts/qwen_voices_gen.go`（1547 个：系统音色 353 + qwen-audio-3.0 plus/flash 基础音色各 597），由 `scripts/gen_qwen_voices.py` 从官方文档与 Excel 生成；官方更新后重跑脚本即可。启动时自动入库（只补缺，不覆盖运营修改）；没有启用的千问账号时这些音色自动隐藏。
- 能力按「模型 + 音色」判定（`tts.CapsFor` / `VoiceCapabilities`）：
  - Qwen-Audio：情绪→行内控制标签（`[sad]` 等），语气标签→富语言标签（`[sighing]` 等），表演指导→`instruction`，强情绪追加指令。
  - CosyVoice 系统音色：不发送指令/标签（官方要求固定格式），只调语速/音高/音量。
  - 多音字：优先 `hot_fix.pronunciation`（保留行内标签）；同一句同字不同读音或 cosyvoice-v2 时改用 SSML `<phoneme alphabet="py">`（`enable_ssml: true`，声调转数字）。不支持 SSML 的音色退回同音字替换。
  - 重新生成会带随机 `seed`，避免得到完全相同的音频。语言非中文时发送 `language_hints`。
- 试听：系统音色直接用官方试听链接（`voices.sample_url`）；基础音色在管理后台「模型与供应商 → 语音合成 → 导入基础音色试听」一键下载官方 214 MB 音频包并入库（任务 `voice_preview_import`）。
- 选角：只从有可用账号的平台音色中选；按角色规则预筛候选（`CastingShortlist`，每角色 10 个、总数 ≤90）再交给大模型；方言/粤语音色不参与普通话书选角；演示引擎音色排在最后。
- 测试：`go test ./internal/ai/tts/`；端到端 `scripts/qwen_smoke.py`（`fake_llm.py` 内置了 DashScope 假接口，key 为 `sk-qwen-test`）。
- 上线配置：管理后台 → 模型与供应商 → 语音合成 → 添加账号 → 预设「千问 AI 平台」→ 填 API Key → 测试 →（可选）导入基础音色试听。

## 表演标签、单句删除、空白建书（2026-11-05，已完成）

- **表演标签（位置化）**：AI 生成画本时，每个单元返回 `cues: [{tag, after}]`（`after` 为插入点前的原文片段，服务端解析为字符偏移）和 `instruction`（≤20 字的表演指导）。原文一字不改，标签单独存储在 `segments.cues`（`[{at, tag}]`）。
  - 词表：`server/internal/ai/tts/cues.go`，对齐 Qwen-Audio：23 个语气风格（影响标签之后的内容）+ 7 个声音效果（在该位置发声）。`GET /api/v1/performance-tags`。旧的整句 `tags`（中文）自动映射到句首。
  - 规则（`core/cues.go` + 提示词第 5/5.1 条）：
    - 只给角色台词加标签，旁白单元的声音标签会被服务端去掉；
    - `instruction` 会去掉「角色台词 / 说话提示语 / 广播剧可删除」之类的说明，按分句截到 24 字；
    - 纯说话提示语不写指导。
  - 合成：
    - Qwen-Audio 音色按位置插入 `[tag]`；
    - 只支持自然语言指导的音色，把语气风格转成 instruction，声音效果忽略；
    - CosyVoice 系统音色不发送。
  - 位置跟随多音字替换（`BuildTTSInputMapped` 的 posMap）进入缓存键。
  - 编辑：修改文字时标签和读音按前后公共部分自动挪位；拆分、合并时随句子分配。
  - 前端 `web/src/components/cues.tsx`：
    - 列表行内显示标签（◆语气 / ♪声音），「我的台词」和提词器同样显示；
    - 片段面板「表演标签」：点字间空隙插入，拖动换位，× 删除；
    - 音色不支持时给出提示。
- **单句删除**：
  - 片段面板标题栏、行悬停都有删除按钮，也可用 Delete / Backspace 键；锁定的句子不删。
  - 删除后焦点移到下一句，toast 可「撤销」（`POST /books/{bid}/segments/restore`，原 id 原位置恢复，已选版本还在则一起恢复）。
  - 批量删除返回 `{deleted, locked}`。
- **空白建书**：
  - 新建图书第一步可选「先创建空白图书」（只填信息）。
  - 「章节」页提供「导入书稿」对话框（上传/粘贴 → 确认章节，组件在 `studio/pages/importer.tsx`，与新建向导共用），调用 `POST /books/{bid}/chapters/import`，新章节接在现有章节之后；书中还没有角色时可勾选导入后分析角色。

  - 后台「优先级」提示写反了：实际是数字大的优先。
  - 对话框打开时聚焦到第一个输入框，而不是关闭按钮。

## 会员订阅与兑换码（2026-11-05，已完成）

- **会员属于用户账号**（`model.UserMembership` 汇总 + `MembershipPeriod` 有效期记录，`core/membership.go`）。
  - 同时有多段会员时，等级（`Plan.Level`）最高的生效：
    - 同一会员再开通会续期；
    - 开通更高等级时，低等级暂停，之后顺延恢复；
    - 开通更低等级时，排在高等级之后生效。
  - 用户拥有的所有工作室都跟随其会员（`Studio.PlanID` 是同步后的结果）。管理员可给工作室指定"签约方案"（`PlanOverrideID`），指定后不再跟随所有者，并每月给该工作室发合同积分。
  - 每分钟由 `MembershipTick` 处理：到期与生效边界、每月发放积分（先认领周期，防止重复发放）、到期前 7 天和 1 天提醒、到期通知。
- **积分随会员赠送**：
  - 每月赠送一次，每段会员首次生效时另送开通礼包（原子认领，防止重复发放）；
  - 发到用户选择的工作室（默认个人工作室），可在自己管理的工作室之间划转，保留原有效期；
  - 创建工作室不再送积分；新用户试用只给权益，不给会员积分（防止刷积分），也不算"开通过会员"。
- **管理员可配置**（后台「会员套餐」，带实时预览）：
  - 价格：月付、年付、划线原价，仅用于展示，支付未接入；
  - 积分：每月赠送、开通赠送、有效期、积分消耗折扣 `CreditRate`；
  - 限额：工作室数（含个人）、每工作室成员、图书、存储、克隆音色（0 表示不含克隆）、单本字数、单文件上传；
  - 其他：排队优先级（作为任务 priority）、导出格式、精品音色、商用授权、功能开关（含新增的分轨导出 `stems`）、卖点、角标、推荐、是否公开。
  - 限额统一返回 `plan_limit` / `plan_required`（含 `kind`、`limit`、`used`）。前端 `components/upgrade.tsx` 全局拦截这类错误，弹出升级提示并列出能解除限制的会员；同时补上了接口错误没有任何提示的问题。
- **兑换码**（`core/redeem.go`，后台「兑换码」）：
  - 可兑换会员（套餐 + 天数，0 表示永久）或积分（数量 + 有效期）；
  - 两种方式：一码一用（批量生成，最多 2 万个，字母表去掉易混字符，可加前缀）、通用口令（可限总份数）；
  - 规则：每人限兑次数、仅限从未开通过会员的用户、开始与截止时间、渠道统计；
  - 兑换先预览再确认，在同一事务里认领，并发下也不会突破每人限兑；有防猜码的频率限制；
  - 管理后台：导出 CSV（带 BOM，Excel 直接打开）、停用批次或单个码、按码查询使用记录；
  - 旧的 PromoCode 已迁移为通用口令批次。
- **页面**：
  - 用户端「会员中心」`/membership`：当前会员、用量、兑换、方案对比（按月/按年）、历史记录；

## 官方配乐库（2026-11-05）

- 来源只收逐首标注为 **CC0 或公有领域** 的纯音乐，可免费商用、无需署名：
  - Wikimedia Commons 上的 Free Music Archive 曲目（按风格分类）和 Musopen 古典录音（逐文件读取授权字段）；
  - OpenGameArt 上手工挑选的 CC0 东方风格曲目。
  - CC BY / BY-SA / NC 全部排除。Pixabay 等站点禁止把音频单独再分发，也不采用。
- `scripts/build_music_catalog.py` 负责抓取和筛选：
  - 筛选条件：授权、时长、人声分类与标题、老唱片和声部分轨、标题黑名单；
  - 分类：按来源分类定风格、按标题关键词定情绪，均衡选曲后生成 `server/internal/core/music_catalog.json`，嵌入后端。
  - 当前 340 首，约 16.7 小时，20 个分类：悬疑推理、恐怖惊悚、史诗热血、冒险奇幻、科幻未来、浪漫言情、温馨治愈、伤感催泪、轻快日常、诙谐喜剧、童话儿童、氛围空灵、钢琴独奏、古典名曲、爵士复古、民谣田园、东方异域、都市轻松、影视配乐、片头片尾。
- 导入：后台「素材库 → 官方配乐库 → 一键导入」，任务类型 `music_import`。
  - 优先下载 Commons 的 MP3 转码，失败时退回原文件；已导入的跳过，可重复运行补全。
  - 每首的作者、来源页面和授权存在 `asset.meta`，素材详情里展示。
  - 导入后，程序合成的演示配乐不再公开，系统片头片尾模板换成配乐库里的曲目。
- 使用：
  - 素材库和混音配乐选择器都有风格分类按钮（`GET /api/v1/music/categories`）；
  - 一键成书按书的题材和标签匹配分类，并按书分散选曲（`pickBGM`）。
- 已知不足：CC0 或公有领域的中国民乐（古筝、二胡、琵琶）几乎找不到，"东方异域"多为日式和中东风格。真正的古风配乐建议接入 AI 音乐生成（接口已预留），或采购、委托创作后上传到素材库。

## 片头片尾：固定音频与每集自动附加（2026-11-06）

- 模板两种做法：`compose` 配乐 + AI 播报（可用 {书名}{章节名}{章节号}{作者}{主播}），`audio` 固定音频（每集原样播放）。
- 固定音频来源：上传（资产类型 `jingle`，不出现在素材库列表）、从资产库选、或用播报配方"AI 生成一段"（`POST /studios/{sid}/templates/generate`，不允许占位符）。最长 3 分钟；渲染时自动电平对齐到正文（-19 dBFS RMS），可再微调 -12~+6 dB。平台要求播报 AI 声明时，接在固定音频之后。
- 播报缓存：`speak` 按"音色 + 最终 TTS 输入"缓存到工作室（preview 资产 + checksum），同样的文字只合成、扣费一次，各集完全一致；重新合成不再重复扣费。
- 每集附加：图书从"不使用"改为选用某模板时，已有章节的混音全部打开片头/片尾（`ApplyBookTemplates`）；在两个模板间切换保留章节的单独关闭。编辑模板会把用它的图书成品标记为需重新合成。
- 片头片尾生成失败会让本章合成失败并给出原因（以前静默丢弃）；模板被删除则跳过。

## MiniMax 语音合成接入（2026-11-06）

- 适配器：`server/internal/ai/tts/minimax.go`，provider 名 `minimax`，默认 base `https://api.minimaxi.com`（`api.minimax.cn` 同样可用，可选 `groupId` 配置会附加 `?GroupId=`）。
  - 同步：`POST /v1/t2a_v2`，非流式、`output_format=hex`、`format=wav`、44.1 kHz 单声道。
  - 异步：`POST /v1/t2a_async_v2` → 轮询 `GET /v1/query/t2a_async_query_v2`（1.5 s 起、逐步放慢到 5 s，最长 30 分钟）→ `GET /v1/files/retrieve_content`。结果按文件头识别 tar / tar.gz / zip / 裸音频，取出其中的音频。
  - 合成方式（账号 `config.synthMode`）：`auto`（默认，超过 3000 字走异步）、`sync`、`async`。
- 请求渲染（`BuildMiniMaxRequest`）：
  - 多音字用行内读音替换该字：`(xing2)`；
  - 2.8 系列把声音类表演标签渲染为语气词：`(laughs)` `(chuckle)` `(sighs)` `(gasps)` `(coughs)` `(clear-throat)` `(snorts)`；
  - 句首的风格标签（悲伤、愤怒、惊慌、耳语…）在没有设情绪时转成整句 `emotion`，句首的「放慢 / 加快」调整语速；
  - neutral 不传 emotion，由模型按文本自动判断；`whisper` 只在 2.6 系列发送；
  - 原文中的英文括号转为全角、去掉控制字符和零宽字符（避免被当成标记或触发「非法字符超 10%」）；
  - 音量 dB → `vol`（0.1–10），音高半音 → `pitch`（−12…12）；
  - `language_boost`：粤语音色或粤语书固定 `Chinese,Yue`，外语书按语言设置，中文书默认不传（可配置为 `auto`）；
  - `text_normalization_mode`（basic / quality）与 `aigc_watermark` 可在账号里开关。
- 能力：`MiniMaxCapabilities(model)`。新增 `Capabilities.TagKeys`：设置后表示只有这些表演标签能在句中演出，前端据此提示「只能演出声音类标签」。
- 限流与重试：
  - 按账号（base URL + key 指纹）在进程内匀速发请求，间隔 = 60 s / 账号的「每分钟请求上限」（默认 20）；
  - 遇到 1002 / 1039 / 2045 / 2056 / 2062 或 HTTP 429 时整个账号暂停 10 s；
  - 限流、并发超限、5xx、网络错误自动退避重试 4 次（2 / 5 / 12 / 25 s）；
  - 其余错误码都翻译成中文提示（密钥无效、余额 / 套餐不足、内容审核、音色不存在、模型无权限或已下线等）。
- `tts.Account` 新增 `RPM`，core 里统一用 `App.ttsAccount(acc)` 构造适配器账号。
- 音色库：
  - `scripts/gen_minimax_voices.py` 根据 `scripts/data/minimax_system_voices.tsv`（官方 327 个系统音色）生成 `minimax_voices_gen.go`；
  - 中文音色手写性别、年龄、风格和旁白标记，外语音色译成中文名并标注语种（如「沉静女声（日语）」），保留官方英文名；
  - 启动时 `seedMiniMaxCatalog` 把每个音色按 `speech-2.8-hd`（精品档）和 `speech-2.8-turbo`（标准档）各登记一条，共 654 条；没有启用 MiniMax 账号时不显示；
  - 群演池只取 Turbo 条目；
  - 管理端「同步音色」调用 `POST /v1/get_voice`，内置表里没有的新音色自动推断语言和性别。
- 试听：
  - 平台音色没有官方试听时，第一次点播放会用默认自我介绍生成试听，不扣积分，并设为该音色的公共试听（`App.adoptVoiceSample`）；
  - 前端 `PlayButton` 新增 `resolve`，`VoicePlay` 统一处理；
  - 试听缓存和片头片尾播报缓存的 key 改为包含供应商账号 ID，与段落音频缓存一致：一个账号（例如测试账号）生成的音频不会被另一个账号复用。
- 升级影响：缓存 key 变化后，已有的试听和片头片尾播报会在下次使用时各重新生成一次。
- 管理端：
  - 预设标为已实现，自动填好模型列表、每分钟 20 次、并发 3；
  - 「MiniMax 合成设置」面板：合成方式、文本规范化、小语种增强、GroupId、音频水印；
  - 默认模型改为带建议列表的输入框。
- 测试：

## MiniMax 音色快速复刻（2026-11-06）

只对接 MiniMax 官方接口；千问平台上转售的 MiniMax 接口不用，合成也一样。

- 适配器（`minimax.go`，实现 `tts.VoiceCloner`）：
  - `POST /v1/files/upload`（purpose=`voice_clone`）上传样本；
  - `POST /v1/voice_clone` 创建音色，参数为 `need_noise_reduction`（跟随「自动降噪」开关）、`need_volume_normalization=true`、试听文本加账号默认模型；
  - 下载返回的 `demo_audio` 作为试听；
  - `POST /v1/delete_voice` 删除，音色已不存在也算删除成功。
  - 不支持专业克隆。
- 音色 ID：`MiniMaxCloneVoiceID(我们的音色 ID, 次数)` 生成 `vb…`，符合 8–256 位、字母开头、只含字母和数字的规则；遇到 2039 重复时换下一个。
- 送审前校验：样本必须是 wav、mp3 或 m4a，10 秒到 5 分钟，不超过 20 MB。`input_sensitive` 命中风控时删除音色并提示原因。
- 复刻相关错误码都翻译成中文：2037、2038（未实名认证）、2048、2051（音质不合格）、2052（名额已满）、1040、1043、1044。
- 新增能力字段（`tts.Capabilities`）：
  - `CloneExpiresUnused`：平台会删除超期未用的复刻音色，且首次合成时计费；
  - `CloneMinSeconds` / `CloneMaxSeconds`：样本时长要求；
  - `ServerDenoise`：平台自己做降噪。
  - MiniMax 的取值：快速复刻、7 天、10–300 秒、平台降噪。
- 复刻任务（`jobVoiceClone`）：
  - `mergeCloneSamples` 用 ffmpeg 把所有样本（浏览器录的 webm 也行）解码、去掉首尾静音，以 0.4 秒间隔拼成一个 32 kHz 单声道 WAV，最长 290 秒，传入 `CloneRequest.MergedPath`；
  - 平台自带降噪时不再做本地 afftdn 降噪；
  - 平台返回试听就用它当样本；`CloneExpiresUnused` 的平台不再在复刻后立刻合成一句，以免当场触发 MiniMax 的音色费用；
  - 复刻完成后发通知。
- 有效期：
  - 复刻后 `expires_at` 设为 7 天后；
  - 第一次真正合成（段落、试听、快速配音、片头片尾播报）时由 `App.voiceUsed` 清除，状态改为「已激活，长期有效」；
  - 到期前 3 天的提醒文案改为「生成任意一句即可长期保留」。
- 选择平台：`designAccount` 先选真实平台，内置演示引擎排在最后。
- `GET /studios/{sid}/voices/clone-options` 返回快速 / 专业克隆各由哪个平台负责、样本时长和有效期规则。
- `StartClone` 会先检查有没有支持该档位的账号，以及样本总时长是否达到平台下限。
- 前端：
  - 克隆页的档位卡片显示「由 MiniMax 复刻 · 样本 10 秒～5 分钟」；只有演示引擎时给出明确警示，没有平台时显示「暂未开放」；
  - 样本不足 10 秒时提示，并且不能进入下一步；
  - 降噪开关注明由 MiniMax 处理，并说明 7 天规则；
  - 音色详情里，未激活的复刻音色会显示截止时间。
- 测试：
  - `go test`：音色 ID 规则；上传和复刻请求体、重复 ID 重试、试听下载、删除；样本过短、专业档、未实名、删除不存在的音色；
  - `minimax_smoke.py` 第 10 部分：10 项检查，包括 webm + wav 合并上传、复刻后不合成、首次使用后激活、删除同步到 MiniMax，全部通过；
  - `full_smoke.py` 新增临时假 MiniMax 账号：克隆会优先走真实平台，没有它的话，接入真实 MiniMax 后冒烟测试会调用真实账号并产生费用。

## 千问声音复刻（2026-11-06）

## 对照专业有声书流程的产品审查（2026-11-08）

参照 ACX/Audible Studios 的审听流程、Pozotron 的制作周期说明、豆包 AI 多人有声剧方案，以及 ElevenLabs、魔音工坊的功能，用新注册账号从导入书稿到导出完整走了一遍。专业流程是：前期（通读、角色、读音表）→ 录制/生成 → 剪辑 → 审听（对照原文逐句听，标记问题句）→ 补录（pickups，只重做问题句）→ 复听 → 母带与技术指标 → 交付检查 → 上架。

发现并修复的问题：
- 前期缺「读音表」入口：后端早有本书读音词典和 AI 提取，但用户端没有页面。新增图书「读音」页（`book/Lexicon.tsx`）：AI 找出易读错的词 → 逐个确认（每个字的读音从下拉里选，不用输入声调）→ 采用；也可以手动添加，或把英文缩写读成别的文字。词条改动后，用到这个词的已配音句子自动标为「有改动」，提示里一键跳到「生成配音 → 有改动的」。生成配音对话框在还没设置读音时会提醒先去设置。
- 读音词典对生僻多音字不生效：原来只对常用多音字应用词典读音，「甄嬛」的「嬛」这类人名用字会被忽略。现在只要字典里有多个读音就按词典读（`core/synth.go`）。
- 审听只有「智能审听」：缺少对照文字边听边标记的人工审听流程。现在「连续播放」从选中句开始，播放的句子高亮并自动跟随；按 M 把正在听的句子标为「待返工」，播放不中断，可以从提示里撤回。被标记的句子在画本里显示红色标记；右侧「片段」里可以选问题类型、补充说明、重新生成、已修复/关闭；右侧「审听」里汇总本章待返工的句子，一键全部重新生成，重新生成后变成「待复核」，可以复听后全部确认关闭。
- 「审听与工单」页新增「导出工单表」（CSV，Excel/WPS 可直接打开），方便把问题清单交给主播或后期。
- 交付前没有总检查：「导出与发布」页顶部新增「交付前检查」，按流程顺序列出画本、逐句配音、成品、技术指标、审听、工单、书名作者、简介、封面、版权、AI 标识，每项未通过都给出原因和「去处理」入口（扩展了 `PrePublishCheck`）。
- 粘贴书稿时书名默认叫「粘贴的文本」：现在会识别开头的书名行和「作者：」行，识别不到就留空并提示填写。
- 制作台顶部主按钮跟着进度走：还有句子没配音时「生成配音（N 句）」是主按钮，配完后「合成」变成主按钮。
- 图书设置改了不保存就离开会丢：现在底部显示「有修改还没保存」，可以撤销修改；离开页面或关闭标签前会确认（通用的 `useLeaveGuard`）。改了停顿、响度、片头片尾等之后，提示里可以一键重新合成所有已合成章节。
- 其他：章节列表没合成的章节显示按语速估算的时长；单句音频长度显示为「2.4 秒」而不是 0:00；修正了「已加入本书读音词典」这条不实提示。

后端：`StaleLinesWithTerms`、`WordReadings`、`GuessTitle`；`GET /pinyin/word`、`POST /books/{bid}/lexicon/activate`；词条增删改返回受影响句数；句子数据带上未关闭工单（`openIssues`/`verifyingIssues`/`issueTitle`）；工单新增 `note`（补充说明/改类型）和 `withdraw`（撤回）操作，并推送章节事件。测试见 `core/workflow_review_test.go`。

## 图片生成：OpenAI GPT Image 与 Google Nano Banana（2026-11-08）

按两家官方最新文档接入，用于 AI 封面和角色头像。原来只有内置抽象图生成器，两家都是「预留接口」。

- **OpenAI GPT Image**（`internal/ai/gen/openai_image.go`，适配器 `openai_image`）
  - 接口：`POST {base}/images/generations`（Image API），Bearer 鉴权，返回 base64；中转服务返回图片链接时自动下载。
  - 默认模型 `gpt-image-2.6-flare`，预设里还有 2.6 sunburst、2.5 flare / sunburst、gpt-image-2、1.5、1-mini。
  - 账号设置：画质（自动 / 低 / 中 / 高）、分辨率（标准 1024 / 高清 2048，仅 gpt-image-2 及以上）、内容审核（标准 / 宽松）、超时。
  - 2K 尺寸满足官方限制：边长为 16 的倍数，比例在 1:3 到 3:1 之间，总像素 655,360–8,294,400。
  - 只在官方地址时发送 `safety_identifier`：用户 ID 的 SHA-256 摘要，不含邮箱。
- **Google Nano Banana**（`internal/ai/gen/gemini_image.go`，适配器 `gemini_image`）
  - 默认走官方文档现在使用的 Interactions API：`POST /v1beta/interactions`，带 `x-goog-api-key` 和 `Api-Revision: 2026-05-20`，`response_format` 为 image、1:1、1K/2K/4K，`store:false`。
  - 可切到旧的 `models/{m}:generateContent`，兼容还没跟上的中转服务。
  - 默认模型 `gemini-nano-banana-2.1`。一次请求只出一张图，最多 3 张并发；部分失败时保留成功的那几张，只按实际张数扣积分。
  - 模型只回文字（比如拒绝）时，把它的回复告诉用户。
- **共同行为**
  - 网络错误、限流和 5xx 自动重试两次。错误信息写成能照着处理的中文，比如：未通过安全审核、需要先完成 OpenAI 组织验证、余额不足、服务器所在地区不支持、Key 无效。
  - 后台「测试」改为调用免费的模型查询接口（OpenAI `GET /models/{m}`，Gemini `models.get`），不再真的生成一张图产生费用。
  - 每次调用记入账号的调用、失败次数和健康状态。
- **选账号**：优先级相同时，真实账号排在内置生成器前面。以前新加的账号按默认优先级 1 保存后，仍然会用内置生成器。路由规则里指定的模型现在对图片 / 音乐 / 音效账号也生效。
- **封面**
  - 接入真实模型后，封面提示词会要求把书名（和作者）排进画面，书名不能有错字，主体放在中央安全区，因为列表会把封面裁成 3:4。

  - 修复：`PATCH /books/{id}` 设置封面时没有校验图片归属，传别的工作室的图片 ID 就能拿到它的签名链接。现在只接受本工作室或平台公共的图片。

## 版本号、PostgreSQL / Redis 与 Docker 发布（2026-11-11，v0.1.0）

**版本号**：
- 根目录 `VERSION`（当前 0.1.0）是唯一来源。
- Go 默认值写在 `server/internal/version`，测试会检查它和 `VERSION` 一致；镜像构建时用 ldflags 写入版本、提交号和构建时间。
- 前端通过 vite define 注入 `__APP_VERSION__`，`web/package.json` 同步为 0.1.0。
- 查看方式：
  - 命令 `voicebook version`；
  - `/healthz` 和 `/api/v1/site` 的 `version` 字段；
  - 后台「运行状态」（含提交号、构建时间、是否使用 Redis）和后台侧栏底部；
  - 帮助中心标题下。

**PostgreSQL**（原来的代码按 SQLite 写成）：
- `db.Like` / `NotLike`：SQLite 的 LIKE 不区分英文大小写，在 PostgreSQL 上用 ILIKE 保持一致；JSON 列（PostgreSQL 上是 jsonb）转成文本再匹配。28 处搜索已替换。
- `db.JSONText`：替换 `json_extract`，用于封面候选、曲库排序和片头片尾模板引用。
- `db.Day`：替换 `substr(created_at)`。
- PostgreSQL 会强制 varchar(n) 长度，SQLite 不会。迁移前把非主键字符串列改为 text，避免长名称写入失败。
- 多个实例同时启动时，迁移、启动时的初始数据和后台初始数据都用 PostgreSQL advisory lock 依次执行。
- 后台「运行状态」在 PostgreSQL 上显示数据库大小。

**Redis**（`VB_REDIS_URL`，新包 `server/internal/bus`）：
- 不配置时一切在进程内完成，适合单实例和本地开发。
- 配置后在实例之间共享：
  - 实时事件：浏览器连在哪个实例都能收到；
  - 任务唤醒，以及取消正在别的实例上运行的任务；
  - 限流计数，按分钟固定窗口；
  - 设置缓存和 TTS 账号缓存的失效；
  - 定时任务锁：每个定时任务每个周期只在一个实例上运行。临时文件清理和本地副本清理仍然每个实例各自执行。
- Redis 暂时连不上时：
  - 消息仍然投递给本实例；
  - 限流退回本实例计数；
  - 定时任务锁拒绝，宁可这一轮不跑，也不重复执行。
- 启动时最多等 Redis 30 秒。

**健康检查与安全**：
- `/healthz` 返回版本、数据库、总线类型，以及启动时初始数据是否还在写入（`seeding`）；数据库或 Redis 不可用时返回 503。
- 新增 `voicebook health` 命令，供容器健康检查使用。
- 生产模式（`VB_DEV=false`）没有设置 `VB_JWT_SECRET` / `VB_SECRET_KEY` 时拒绝启动。

**Docker**：
- `Dockerfile` 在构建机本身的架构上构建前端和 Go 程序（Go 交叉编译），输出 linux/amd64 与 linux/arm64 镜像。运行环境为 debian trixie-slim + ffmpeg，以非 root 用户（uid 10001）运行，自带 HEALTHCHECK。
- `docker-compose.yml`：应用 + postgres:17-alpine + redis:7-alpine，带健康检查依赖；`.env` 里的 `VB_VERSION` 决定部署哪个版本，必填项缺失时会给出中文提示。
- `docker-compose.build.yml`：改为从源码构建镜像。

**CI**（`.github/workflows/ci.yml`）：
- 每次推送运行以下任务：
  - 版本一致性检查；
  - SQLite 上的 Go 测试；
  - PostgreSQL 17 + Redis 7 上的 Go 测试：`dbtest.Open` 为每个测试建一个独立 schema，bus 测试连真实 Redis；
  - 前端构建；
  - 端到端：两个实例共用 PostgreSQL + Redis 同时启动，跑 `smoke.py`、`full_smoke.py`、`cluster_check.py`（跨实例事件、限流、缓存）。
- 全部通过后构建并推送镜像：main 推送得到 `edge` 和 `sha-xxxxxxx`；标签推送得到 `X.Y.Z`、`X.Y`、`latest`。随后用 docker compose 拉取刚推送的镜像实际部署一次，确认版本号以及确实连着 PostgreSQL + Redis。
- 标签推送最后根据 `CHANGELOG.md` 创建 GitHub Release。
- `smoke.py` / `full_smoke.py` 现在可以用 `VB_BASE` 指向任意实例，有失败时退出码不为 0。

**本机验证**（本机不安装 PostgreSQL 和 Redis）：
- Go 测试全部通过。其中 bus 测试使用内存版 Redis（miniredis），覆盖两个实例共享消息、锁、限流，以及 Redis 中断后的退化行为。
- 全新的 SQLite 实例上：`smoke.py` 150 项、`full_smoke.py` 219 项全部通过。
- 两个实例共用 SQLite 文件和内存版 Redis 时，`cluster_check.py` 11 项全部通过。
- PostgreSQL 与 Redis 的真实验证在 GitHub Actions 上进行。

## 音乐生成：Suno（2026-11-10）

**接入方式**：
- Suno 官方目前没有公开的 API：platform.suno.com 只有登录页，没有公开文档，开发者 API 仍在合作伙伴阶段。
- 现在实际可用的是 New API / One API 等中转服务的 Suno 渠道，协议如下：
  - `POST /suno/submit/music` 提交任务，返回任务编号；
  - `GET /suno/fetch/{任务编号}` 查询进度；
  - 任务完成后下载两首 mp3。
- 适配器在 `server/internal/ai/gen/suno.go`，协议参考 https://doc.newapi.pro/en/api/suno-music 。

**管理后台**（模型与供应商 → 音乐生成 → 添加账号 → 预设「Suno（New API / One API 中转）」）：
- 接口地址填中转服务的根地址；如果误填了末尾的 `/v1`，会自动去掉。
- API Key 填中转服务的令牌。
- 模型可选 chirp-v4、chirp-v3-5、chirp-auk（v4.5）、chirp-bluejay（v4.5+）、chirp-crow（v5），以中转服务支持的为准。
- 「Suno 生成设置」可以调查询间隔（默认 5 秒）和最长等待时间（默认 10 分钟）。
- 「测试」只查询一个不存在的任务，用来验证地址和密钥，不生成歌曲、不产生费用。错误分三类说明：密钥无效、地址不是 Suno 中转、连不上。

**生成**（资产库 → AI 生成 → 背景音乐）：
- 配置了 Suno 时，表单多出几项：
  - 类型：纯音乐，或带人声的歌曲（片头曲、片尾曲、插曲）；
  - 风格；
  - 歌名和歌词，带人声时才有。
- 时长滑块隐藏，因为时长由 Suno 决定，通常 2–4 分钟。
- 数量为 2 首或 4 首，每次请求出 2 首。
- 新接口 `GET /studios/{sid}/generate/options` 告诉前端当前音乐服务支持什么。
- 填写方式与请求模式：
  - 只写描述：走 Suno 的描述模式，由 Suno 写词、定风格。
  - 填了风格、歌名或歌词：走自定义模式。
  - 纯音乐不会发送歌词。
- 结果保存与扣费：
  - 两首都保存到资产库，标签为「AI 生成 / Suno / 纯音乐或歌曲」，歌词存在素材详情里。
  - 授权显示为「以生成服务（Suno）的条款为准，请自行确认能否商用」，不写「可商用」。生成表单底部也加了第三方服务的提示。
  - 任务编号记在任务的 payload 里，方便到服务方后台查询。
  - 按请求的数量扣积分；服务方多给的不收费；失败不扣费。
- 提交任务的重试规则：
  - 只在服务方明确拒绝时重试（429 / 502 / 503）。
  - 网络中断或 500 不重试，避免同一首歌被收两次钱。
  - 查询进度时网络出错，可以容忍连续 5 次。
- 下载限制：只跟随 http(s) 地址，单个文件最大 64 MB，按文件头识别音频格式；拿到错误页时会报错，不会当成音频存下来。

**测试**：
- Go 单元测试 11 个（`suno_test.go`），覆盖：
  - 描述模式与自定义模式；
  - 任务失败；
  - 一首失败、另一首保留；
  - 错误密钥；
  - 只重试被拒绝的提交；
  - 超时；
  - 拒绝非音频文件；
  - 测试按钮不提交任务。
- `scripts/fake_cloud.py` 增加了本机 Suno 中转替身（密钥 vb-suno-key，生成 8 秒的 mp3；描述里含「失败」时任务失败）。
- 端到端 19 项：在开发服务器上临时加一个优先级 1000 的替身账号，覆盖：
  - 测试按钮；
  - 生成选项；
  - 纯音乐和歌曲两种请求；
  - 两首都保存，ffprobe 读出时长；
  - 授权和标签；
  - 扣费；
  - 失败不扣费。
  
  测完已删除替身账号和生成的素材，真实账号调用次数不变。

## 文件存储：阿里云 OSS（可选，2026-11-08）

后台「系统设置 → 文件存储」可以选「本机磁盘」或「阿里云 OSS」。不配置时和以前一样存在服务器的 `data/storage`。

- **范围**：用户上传的书稿、录音、封面、头像，以及生成的配音、成品、导出文件、波形数据，都走同一个存储层（`storage.Store`）。`tmp/` 下的临时文件始终留在本机。
- **工作方式**（`server/internal/storage/store.go`）：
  - 文件先写到本机（ffmpeg 要读本地文件），开启 OSS 时同步上传，成功后记入 `stored_objects` 表。
  - 上传失败只记日志，文件留在本机照常可用，下次「上传到 OSS」时补传。
  - 本机副本丢失或被清理后，第一次用到时自动从 OSS 取回（同一文件并发只下载一次）。
  - 删除文件时同时删 OSS 上的副本。
- **下载方式**：站内链接仍是原来带 HMAC 签名的 `/files/...`，权限校验不变。校验通过后有两种方式：
  - 浏览器直连（推荐）：302 跳转到 1 小时有效的 OSS 签名链接，存储桶保持私有。
  - 经服务器转发：由本站读出文件返回。
  前端只用 `<audio>`/`<img>` 播放和显示，不需要给存储桶配置跨域。
- **SDK**：用阿里云官方 Go SDK v2（`alibabacloud-oss-go-sdk-v2` v1.6.1），V4 签名。
- **后台配置项**：
  - 地域、存储桶、AccessKey（Secret 加密保存，不回显）。
  - 访问方式、本机副本保留天数（默认 7 天，0 表示一直保留）。
  - 更多选项：内网传输（同地域 ECS）、自定义域名或 CDN、路径前缀、自定义 Endpoint。
- **保存与运维**：
  - 「测试连接」依次检查上传、读回、浏览器直连签名链接、删除。保存时如果选的是 OSS，会先跑一遍测试，不通过就不保存。常见错误会翻译成可操作的说明（AccessKey 不存在、Secret 错误、存储桶不存在、地域不对、没有权限、内网地址连不上）。
  - 「文件分布」显示本机和 OSS 各有多少文件、多少还没上传；「上传到 OSS」在后台补传开启前的旧文件，并显示进度。
  - 每 12 小时清理一次本机副本：只删超过保留天数没用到、并且已经确认 OSS 上大小一致的文件。
  - 切回本机磁盘后，新文件只存本机；已经在 OSS 的文件仍从 OSS 读取，所以要保留 AccessKey。
- **测试**：
  - `internal/storage/store_test.go` 用本地假 OSS 覆盖：上传、签名链接下载、清理后取回、补传、删除、转发模式、上传失败不影响写入，以及三种地址形式（公网、内网传输、自定义域名）。
  - 端到端（独立测试实例 + `scripts/fake_cloud.py`）22 项通过。

## 第三方登录：标准 OAuth 2.0 / OpenID Connect（2026-11-08）

原来只有写死的 Google 和微信两个入口，现在改成在后台「系统设置 → 第三方登录」自由添加：

- **预设**：GitHub、Google、Microsoft、GitLab、Gitee、微信（开放平台扫码），以及通用 OpenID Connect 和通用 OAuth 2.0。
  - 预设只需填 Client ID 和 Secret。
  - 通用 OIDC 填签发方地址，其余地址自动发现。
  - 通用 OAuth 2.0 填三个地址和用户信息字段的位置。
  - 每个登录方式都有可复制的回调地址。
- **协议**（`server/internal/core/oauth.go`）：
  - 授权码模式（RFC 6749）加 PKCE S256（RFC 7636）。
  - `state`、PKCE 校验码和 nonce 放在加密的 HttpOnly Cookie 里，回调只能在发起登录的同一个浏览器完成，防止登录 CSRF。
  - OpenID Connect 的身份令牌用 JWKS 验签（RS/PS/ES/EdDSA，以及用 Client Secret 的 HS），并核对签发方、受众、azp、有效期和 nonce；Microsoft 多租户的 `{tenantid}` 签发方按令牌里的 `tid` 匹配。
  - 用户信息接口返回的 sub 必须与身份令牌一致。
  - 客户端认证支持 `client_secret_basic`（按规范先做表单编码）和 `client_secret_post`，OIDC 默认按服务商公布的方式选择。
  - 服务商地址必须是 https（本机地址除外，便于测试）。
- **账号规则**：
  - 已绑定的第三方账号直接登录；停用的账号不能登录。
  - 邮箱已注册过的人不会被自动关联，否则别人可以用一个声称同邮箱的第三方账号接管账号。页面提示先用原方式登录，再到「账号设置」绑定。
  - 新用户注册前必须在登录页同意协议，同意记录随登录流程带到服务端。只有第三方确认过的邮箱才写进账号（GitHub、Gitee 读邮箱列表里已验证的主邮箱）。
  - 每个登录方式可以关闭「允许直接注册」；平台关闭注册或邀请制时，不能用第三方新建账号。
  - 「账号设置 → 第三方账号」可以绑定和解除绑定，每个登录方式只能绑定一个。绑定时只认当前浏览器里登录的账号。旧版在网址里传访问令牌的做法已去掉。
- **测试**：
  - `internal/core/oauth_test.go` 用本地假身份服务覆盖：注册与再次登录、邮箱不自动关联、绑定与防抢占、关闭注册、state 和 Cookie 篡改或过期、拒绝授权、身份令牌的 nonce/受众/签发方/过期/签名错误、HS256、未验证邮箱、Microsoft 租户、GitHub 式 OAuth 2.0 主邮箱。
  - 浏览器端到端 20 项通过，覆盖后台添加、登录页按钮、协议确认、注册、邮箱冲突、绑定、用绑定账号登录、拒绝授权。
